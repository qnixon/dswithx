Naive Bayes classifies by asking which label makes the observed features most
probable. It is "naive" because it assumes the features are independent given
the label, which lets each one be counted separately.

## The dataset

`data.csv` holds 200 synthetic emails labelled `spam` or `ham`, with three
yes/no features: `has_link`, `mentions_money`, and `known_sender`. The `split`
column marks 150 rows as `train` and 50 as `test`. It was generated once by
`make_data.py` (fixed seed 20261102) and committed.

## The math

From the training rows, count everything. For a test email with feature values
$v_1, v_2, v_3$, the score of label $c$ is

$$
\log P(c) + \sum_{j} \log P(v_j \mid c)
\qquad\text{where}\qquad
P(c) = \frac{n_c}{n}
\quad
P(v_j \mid c) = \frac{n_{c,v_j} + 1}{n_c + m_j}
$$

$n_c$ is the number of training emails with label $c$, $n_{c,v_j}$ the number
of those whose feature $j$ is $v_j$, and $m_j$ the number of distinct values
feature $j$ takes (here 2). Adding 1 to every count (Laplace smoothing) keeps
an unseen combination from zeroing out a label. Logs turn the product of
probabilities into a sum.

The predicted label is the one with the higher score; an exact tie would go
to the alphabetically first label.
